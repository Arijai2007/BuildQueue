# BuildQueue REST API

Start `./buildqueue --serve --port 8080`. Default host is `127.0.0.1`; port range 1024–65535. All assets are served locally from `web/`. Responses use `{"ok":true,"data":...}` or `{"ok":false,"error":"..."}`. Submit returns 201; normal operations 200; invalid input 400; missing job/route 404; cross-origin POST 403; non-JSON POST 415; internal errors 500. Send `Content-Type: application/json`, even for empty `{}` controls. Maximum body is 65536 bytes. No CORS permissions or arbitrary shell commands are exposed.

| Method | Endpoint | Body / result |
|---|---|---|
| GET | `/api/health` | product name, healthy status |
| GET | `/api/jobs` | job snapshot array |
| GET | `/api/jobs/{id}` | one job or 404 |
| GET | `/api/memory` | real partition map, policy, size and fragmentation stats |
| GET | `/api/resources` | active, available, peak slots and atomic counter |
| GET | `/api/stats` | logical metrics and completed sample count |
| GET | `/api/gantt` | `{worker,job,start,end,dispatch}` interval array; job 0 is idle; dispatch serial preserves quantum boundaries |
| GET | `/api/log` | latest 4000 events with logical tick and wall epoch milliseconds |
| GET | `/api/config` | policy, quantum, workers, slots, memory, mode, delay |
| GET | `/api/demos` | allowed scenario names |
| GET | `/api/snapshot` | one coherent copy of all dashboard state |
| POST | `/api/submit` | `{name,type,arrival,burst,priority,memory,arrival_now?}` → `{id}` |
| POST | `/api/cancel` | `{id}`; rejects RUNNING and terminal jobs |
| POST | `/api/policy` | `{policy:"fcfs"|"sjf"|"priority"|"rr",quantum:2}` |
| POST | `/api/memory-policy` | `{policy:"first"|"best"|"worst"}` |
| POST | `/api/workers` | `{workers:4}`; same validated configuration path |
| POST | `/api/config` | optional `{workers,slots,memory,mode,delay_ms}` |
| POST | `/api/run` | `{}`; asynchronous, stops when no unfinished jobs remain |
| POST | `/api/pause` | `{}`; returns after current tick transaction |
| POST | `/api/resume` | `{}`; same as run |
| POST | `/api/step` | `{}` → `{advanced:true|false}`; rejects while running |
| POST | `/api/reset` | `{}`; reclaims resources and preserves configuration |
| POST | `/api/load-demo` | `{name:"fragmentation"}`; validates and atomically replaces experiment |
| POST | `/api/compare` | `{}`; four isolated replays of the current original input specs |
| POST | `/api/clear-log` | `{}`; clears only in-memory view, preserves disk log |

Validation ranges: printable name 1–80 chars, burst 1–10000, arrival current tick–100000, priority 0–99, memory 1–capacity, workers 1–16, slots 1–32, total simulated memory 1–1048576 MB, delay 0–5000 ms, quantum 1–1000. Fields omitted on submit use documented JobSpec defaults: name `Build task`, type `simulated`, arrival 0, burst 4, priority 3, memory 128. At a nonzero clock supply the current or a future arrival explicitly.

```sh
curl http://127.0.0.1:8080/api/health
curl -H 'Content-Type: application/json' -d '{"name":"fcfs"}' http://127.0.0.1:8080/api/load-demo
curl -H 'Content-Type: application/json' -d '{}' http://127.0.0.1:8080/api/step
curl http://127.0.0.1:8080/api/snapshot
curl -H 'Content-Type: application/json' -d '{}' http://127.0.0.1:8080/api/compare
```

`worker` is zero-based and −1 when unassigned. `first_run`/`completion` use −1 until recorded; response/turnaround are JSON null when not defined. A completed process job includes `process_pid`, `process_exit`, `process_wall_ms`, `process_error`; completion records finished execution, while a nonzero process exit records failure.

Comparison captures one immutable set of original JobSpecs and resource settings, then runs fresh simulation engines from tick zero. Cancelled inputs remain part of the original submitted workload. Parent jobs, remaining burst, metrics and event log are not mutated. All four runs have identical worker count, memory capacity, memory policy and slots; RR uses the current configured quantum. Default demos for textbook comparisons use one worker and ample memory. No persistent comparisons are stored in the C++ engine; exports are generated by the browser from actual returned results.

## Final audit schema clarifications

- `arrival_now` is an optional boolean on submit. When true, arrival is set to the engine tick while holding its lock. Without this flag, the existing arrival default remains zero. Non-boolean values return 400.
- Missing/nonpositive cancellation IDs, malformed or overflowing path IDs, and missing `workers` on `/api/workers` return 400. A valid but nonexistent positive ID returns 404.
- Unsupported API methods return 405 with the normal JSON error envelope; oversized request bodies return 413 with JSON. POST media types must be application/json (parameters such as charset are allowed).
- `/api/snapshot` adds `experiment_revision`, `scenario` and `logging:{enabled,healthy,persisting,error}`. `/api/compare` adds `source_revision` identifying the captured input/configuration revision. Playback ticks do not change that revision.
- The server rejects a second listener on the same port. The default remains loopback-only; an alternate port does not change the API paths.
